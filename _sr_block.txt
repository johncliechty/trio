## Wave 1 — W1 — Brownfield contracts: SUPERSEDES/REUSE, package & capability schemas

**Intent:** Lock extension-only brownfield map and machine-checkable package/capability/readiness/SOURCES contracts so every later wave extends one distro stack and cannot ship Anchor-only.

**Deliverables:** GREEN inventory + gap-proof map (path→NS criterion) citing distro.py, vendor_skills.py, onboard.py, registrar, publish_distro, scrub/clean-scan; SUPERSEDES + REUSE map artifact forbidding second publish path and Tailscale/onboard2 reimplementation without gap-proof ticket; package_matrix schema (A Skills-only | B Anchor+Skills; hard-block Anchor-only names; B⊇A; skills_pin); per-skill capability matrix (works-without-Anchor | degraded-without-Anchor | Anchor-required) for Trio+Foundry roster; readiness stamp schema (ready | degraded + reason codes); SOURCES.md multi-repo pin schema + skill freeze tag placeholders; unit tests validating schemas and Anchor-only rejection

**Depends on:** —

**done-when:** Schemas and SUPERSEDES/REUSE map land with tests that reject Anchor-only package names and assert B must declare skills_pin and contain full Skills subtree contract.

- **Given** A package matrix document names an Anchor-only artifact, **when** the package_matrix validator runs, **then** validation fails closed and no ship-allowed stamp can be produced
- **Given** Capability matrix lists Zombie Hunter / Tidy-Idy / Anchor Doctor, **when** Skills-only roster is derived, **then** Anchor-required surfaces are excluded or degraded-labeled, never crash-on-missing-Anchor
- **Given** A Foreman wave template omits reuse-proof path, **when** contract lint runs, **then** lint fails until reuse path or gap-proof ticket is present

## Wave 8 — W8 — Friction feedback core: schema, fail-closed sanitizer, de-identified install key

**Intent:** Build the only allowed global improvement feed substrate: structured per-skill friction exports that fail closed and never send session content or PII.

**Deliverables:** structured friction schema at journal-append time (skill_id+version from SOURCES/manifest, outcome class, structural codes, duration/complexity bands, OS class, model-family seats, workaround enums/bounded tokens); sanitizer: allowlist fields only; PII/path/prompt/session-purpose detectors on every string; hard-drop on hit; fail closed if unclean; de-identified install key: high-entropy random UUID on opt-in only; never hash email/username/machine/path; rotate/wipe with continuity-break warning; local full journals remain local; no retro-upload on later opt-in; opt-out stops sends and may wipe key; local queue rules: send only while consent valid; never send after mid-queue opt-out; schema-versioned journal + feedback contracts (semver) with unit tests

**Depends on:** W7 — Onboard seats, feedback consent, Anchor desktop/service, pin-mismatch

**done-when:** Sanitizer red-team unit suite drops planted PII/paths/secrets/session-purpose and sends nothing when unclean; install key is opaque random and opt-in-only.

- **Given** A journal entry contains an absolute user path and session-purpose prose, **when** sanitizer builds an export while user is opted in, **then** record is dropped and nothing is sent (fail closed)
- **Given** User has never opted in, **when** export pipeline is invoked, **then** no install key exists and no payload is produced
- **Given** User opts in then opts out with key wipe while items remain queued, **when** queue drain runs, **then** no further sends occur and key is wiped
