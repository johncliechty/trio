## Wave 1 — W1 — Brownfield contracts: SUPERSEDES/REUSE, package & capability schemas

**Intent:** Lock extension-only brownfield map and machine-checkable package/capability/readiness/SOURCES contracts so every later wave extends one distro stack and cannot ship Anchor-only.

**Deliverables:** GREEN inventory + gap-proof map (path→NS criterion) citing distro.py, vendor_skills.py, onboard.py, registrar, publish_distro, scrub/clean-scan; SUPERSEDES + REUSE map artifact forbidding second publish path and Tailscale/onboard2 reimplementation without gap-proof ticket; package_matrix schema (A Skills-only | B Anchor+Skills; hard-block Anchor-only names; B⊇A; skills_pin); per-skill capability matrix (works-without-Anchor | degraded-without-Anchor | Anchor-required) for Trio+Foundry roster; readiness stamp schema (ready | degraded + reason codes); SOURCES.md multi-repo pin schema + skill freeze tag placeholders; unit tests validating schemas and Anchor-only rejection

**Depends on:** —

**done-when:** Schemas and SUPERSEDES/REUSE map land with tests that reject Anchor-only package names and assert B must declare skills_pin and contain full Skills subtree contract.

- **Given** A package matrix document names an Anchor-only artifact, **when** the package_matrix validator runs, **then** validation fails closed and no ship-allowed stamp can be produced
- **Given** Capability matrix lists Zombie Hunter / Tidy-Idy / Anchor Doctor, **when** Skills-only roster is derived, **then** Anchor-required surfaces are excluded or degraded-labeled, never crash-on-missing-Anchor
- **Given** A Foreman wave template omits reuse-proof path, **when** contract lint runs, **then** lint fails until reuse path or gap-proof ticket is present

## Wave 2 — W2 — No-leak distro substrate: roster canary, denylist scrub, SOURCES provenance

**Intent:** Expand freeze-at-tag vendoring and deny-by-default scrub so full-roster packaging cannot leak author data or ship from dirty mid-run trees.

**Deliverables:** vendor_skills.py roster config extended toward full declared suite via config-only changes; canary: one large Foundry skill + one Trio skill through git-archive → denylist → residual scrub → SOURCES.md; expanded denylist + residual host-path/secret scrub; dual CI fixtures: planted-leak fails clean-scan; planted-legit skill-prose paths pass; SOURCES.md attestation fields (multi-repo freeze tags/commits, package versions, scrub tool versions, ship-allowed gate text); money-safe packaging tests (network deny default; mock archive fixtures only)

**Depends on:** W1 — Brownfield contracts: SUPERSEDES/REUSE, package & capability schemas

**done-when:** Canary archive for roster expansion is scrub-green; planted-leak fixture fails clean-scan; planted-legit fixture passes; SOURCES pin schema is written for freeze tags.

- **Given** A fixture tree plants an author host path and a secret token, **when** clean-scan runs on the scrubbed archive, **then** publish is blocked and the leak is reported
- **Given** A legitimate skill doc mentions a relative path pattern, **when** clean-scan runs, **then** scan passes (no false-positive block)
- **Given** Working tree is dirty mid concurrent skill run, **when** publish pipeline is invoked, **then** dirty-tree gate fails before any artifact is emitted

**Depends on:** W2 — No-leak distro substrate: roster canary, denylist scrub, SOURCES provenance

**done-when:** CI publish job green only for A or B with B⊇A and skills_pin; Anchor-only names hard-fail.

- **Given** A release job requests package type Anchor-only, **when** publish matrix gate runs, **then** job fails and no artifact is produced
- **Given** Package B is assembled without skills_pin or missing a required Skills subtree entry, **when** B⊇A / skills_pin asserts run, **then** publish fails closed
- **Given** Package A Skills-only is requested, **when** publish runs, **then** artifact emits without Anchor service binaries and still includes governance/seat setup hooks contract

## Wave 5 — W5 — Consumer install model, readiness stamp, skills immutability seal

**Intent:** Make Skills install consumer-safe with machine-readable readiness and forked-tree detection so green ready is honest and feedback cannot export from broken immutability.

**Deliverables:** consumer skill install model (read-only-by-default or clear overlay; re-vendor for updates); onboard path labels: consumer vs collaborator vs Foundry-edit; post-onboard checksum/manifest seal of vendored skills; local edits → degraded forked status; machine-local home config root for projects/skills/Anchor without embedding author paths in shipped trees; readiness stamp on disk: ready requires governance installed + ≥1 coding-family seat probe pass OR explicit user-accepted degraded; Skills refuses green ready otherwise; tests for seal mismatch and readiness reason codes

**Depends on:** W4 — Governance pack generator + Foundry journal layout hooks

**done-when:** Ready stamp is green only with governance + seat probe or explicit degraded; skill tree edits flip seal to forked and block feedback export path.

- **Given** Governance is installed but no coding-family seat probe has passed and user has not accepted degraded, **when** readiness is evaluated, **then** stamp is not green ready and reason codes explain the gap
- **Given** Vendored skills manifest is sealed at onboard, **when** a local skill file is modified, **then** status becomes degraded forked and feedback export is disabled until re-vendor
- **Given** User chooses a home directory, **when** machine-local config is written, **then** skills and future projects resolve under that root without author paths in package trees

## Wave 6 — W6 — Plain-English onboard core: home, prereqs, permissions, refuse-don't-clobber

**Intent:** Deliver resumable terminal onboard that explains home, asks before writes, fails early on prereqs, and never destroys foreign skill installs.

**Deliverables:** scripted dialog tree: home explain (recommend C:\dev on Windows; overridable); permission gates before AGENTS.md/pointers, model prefs, skill links/copies, service registration; resumable onboard state file; transactional rollback manifest; preflight collision scan (foreign skills, OneDrive Desktop, existing Anchor data); alternate root offer; one upfront actionable prereq list; fail early with fix links; refuse-don't-clobber tests against pre-seeded foreign skill dirs; idempotent re-run tests

**Depends on:** W5 — Consumer install model, readiness stamp, skills immutability seal

**done-when:** Onboard is resumable, permission-gated, and refuse-don't-clobber proven against foreign skill dirs; prereq failures surface as one upfront list before writes.

- **Given** Chosen home already contains a foreign skill install, **when** onboard skill-install step runs, **then** foreign tree is left intact; onboard refuses clobber and offers alternate path
- **Given** Required Python/node/CLI prereqs are missing, **when** onboard starts, **then** a single actionable prereq list is printed and no config writes occur
- **Given** Onboard is interrupted mid-way, **when** onboard is re-run, **then** state file resumes without re-prompting completed permission steps or destroying prior work

## Wave 8 — W8 — Friction feedback core: schema, fail-closed sanitizer, de-identified install key

**Intent:** Build the only allowed global improvement feed substrate: structured per-skill friction exports that fail closed and never send session content or PII.

**Deliverables:** structured friction schema at journal-append time (skill_id+version from SOURCES/manifest, outcome class, structural codes, duration/complexity bands, OS class, model-family seats, workaround enums/bounded tokens); sanitizer: allowlist fields only; PII/path/prompt/session-purpose detectors on every string; hard-drop on hit; fail closed if unclean; de-identified install key: high-entropy random UUID on opt-in only; never hash email/username/machine/path; rotate/wipe with continuity-break warning; local full journals remain local; no retro-upload on later opt-in; opt-out stops sends and may wipe key; local queue rules: send only while consent valid; never send after mid-queue opt-out; schema-versioned journal + feedback contracts (semver) with unit tests

**Depends on:** W7 — Onboard seats, feedback consent, Anchor desktop/service, pin-mismatch

**done-when:** Sanitizer red-team unit suite drops planted PII/paths/secrets/session-purpose and sends nothing when unclean; install key is opaque random and opt-in-only.

- **Given** A journal entry contains an absolute user path and session-purpose prose, **when** sanitizer builds an export while user is opted in, **then** record is dropped and nothing is sent (fail closed)
- **Given** User has never opted in, **when** export pipeline is invoked, **then** no install key exists and no payload is produced
- **Given** User opts in then opts out with key wipe while items remain queued, **when** queue drain runs, **then** no further sends occur and key is wiped
