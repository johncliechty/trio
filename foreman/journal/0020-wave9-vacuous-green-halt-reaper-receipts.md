# Lesson 0020: Vacuous-GREEN Halt Triggered by Tracked Runtime Ledger Files

## Context
During Wave 9 of the Anchor shareable build, Foreman's orchestrator triggered a `vacuous-GREEN HALT` because the GREEN gate did not exercise any changed source file. The orchestrator reported that `.anchor/reaper_receipts.jsonl` was modified, but no test reaches it.

## Cause
`.anchor/reaper_receipts.jsonl` and files in `.anchor/usage_ledger/` are runtime ledgers generated by the application. Because `foreman.config.json` had `git.enabled: false`, Foreman bypassed `git ls-files` and used its fallback manual hashing diff (`changedSince`), which relies solely on the `IGNORE_DIRS` list in `wave-engine.mjs`. Because `.anchor` was missing from `IGNORE_DIRS`, Foreman scanned it, saw the runtime ledger modifications, and incorrectly flagged them as source file changes that were not exercised by tests.

## Resolution
A pair-programming intervention updated `IGNORE_DIRS` in `C:\dev\trio\foreman\bin\wave-engine.mjs` to explicitly include `.anchor`. In addition, since the ledger files were accidentally tracked by git anyway, they were removed with `git rm --cached` and added to `.gitignore` to maintain proper repository hygiene.

## Future Prevention
When introducing new runtime generated directories (especially those acting as databases or logs), they must be added to the orchestrator's `IGNORE_DIRS` fallback list in addition to being ignored by git, to ensure they do not falsely trigger halts when the build runs with git integration disabled.
